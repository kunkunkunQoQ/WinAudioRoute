## Summary

First public preview of WinAudioRoute: a .NET library and CLI for Windows audio devices, sessions,
per-application routing and automation.

- **Library**: `WinAudioRoute` 0.1.0 — class library, `net8.0-windows10.0.19041.0`, no third-party runtime dependencies
- **CLI**: `winaudio` — `devices`, `sessions`, `default`, `default-output`, `default-input`, `volume`, `mute`, `unmute`, `route`, `reset`, `capabilities`
- **Samples**: `DeviceSwitcher`, `PerAppRouting`, `SessionMonitor`
- **Platforms**: Windows 10 2004+ / Windows 11, x64; ARM64 build supported, runtime experimental

## What's in the box

### Devices

```csharp
using var audio = new WindowsAudioManager();

audio.GetPlaybackDevices();
audio.GetRecordingDevices();
audio.GetDevices(AudioDataFlow.Render, AudioDeviceState.All);   // includes disabled / not present / unplugged
audio.GetDefaultDevice(AudioDataFlow.Render, AudioRole.Communications);
audio.ResolvePlaybackDevice("Speakers");                        // exact ID -> exact name -> unique substring
audio.SetDefaultDevice(device, AudioRole.Console);
```

### Sessions and application volume

```csharp
audio.GetSessions();                          // session granularity: one PID can own many sessions
audio.GetSessionsForProcess("chrome.exe");    // ambiguous names throw with the candidate PIDs
audio.GetApplicationVolume(pid);
audio.SetApplicationMute(pid, true);
audio.GetDeviceVolume(device);
```

### Per-application routing

```csharp
if (audio.IsPerAppRoutingSupported)
{
    audio.SetApplicationOutput(pid, speakers);
    audio.GetApplicationOutput(pid);          // null = "follow the system default device"
    audio.ResetApplicationRouting(pid);
}
```

### Events

```csharp
audio.DeviceChanged  += (_, e) => …;   // added / removed / state / default / property
audio.SessionChanged += (_, e) => …;   // created / disconnected / state / volume / …
audio.NotificationHandlerFaulted += (source, ex) => …;
```

### CLI

```powershell
winaudio devices --json
winaudio volume chrome 35
winaudio route game.exe --output "Speakers"
winaudio capabilities --json
```

## Design commitments

| Commitment | How it is enforced |
| --- | --- |
| Zero third-party runtime dependencies | No `PackageReference` in the library; verified by `eng/verify-package.ps1` |
| No UI framework leakage | The library references no WPF/WinForms/tray/OSD type |
| Every public API documented | `XmlDocumentationTests` reflects over the public surface and requires an XML entry for each member |
| COM references owned explicitly | One owner per reference, released exactly once; audited in `docs/COM_REFERENCE_OWNERSHIP.md` |
| Failure carries the HRESULT | Typed exceptions plus `AudioOperationResult` with per-target failures |
| Undocumented APIs are disclosed | `usesUndocumentedApi` in JSON, `RoutingCapability` at runtime, warnings in README and XML docs |
| Synchronous by contract | No fake `Task`/`CancellationToken` wrappers around synchronous COM calls |

## Breaking / notable changes

This is the first release, so there is no migration path to document. Two behaviours are worth
calling out because they are deliberate and easy to misread:

1. **Volume is a `float` scalar in 0.0–1.0, and out-of-range values are clamped, not thrown.**
   The `*Percent` helpers take and return `int` 0–100.
2. **A `float` query parameter means absolute volume; `0` means silence, not "unchanged".**
   To nudge relative volume, read the current value and write the sum.

---

## Known limitations

1. **Per-app routing uses `Windows.Media.Internal.AudioPolicyConfig`, an undocumented Windows internal
   API.** No public API exists for per-application endpoint selection. Availability is probed at
   runtime; if Microsoft changes it, routing will report unsupported rather than crash. Verified only
   on Windows 11 build 26100.
2. **ARM64 has not been hardware-verified.** It cross-compiles; no ARM64 machine was available.
3. **No global "reset all applications" API.** Only per-process resets are exposed, on purpose.
4. **Device and session change events are push-based with no polling loop.** Device notifications are
   registered for cache invalidation; session notifications are registered lazily on first subscription.
5. **No `net48` target.** .NET 8 only for 0.1.0.
6. **The library does not run in 32-bit processes.** That is asserted at startup rather than left to fail later.

### CI vs. real audio

> CI verifies builds, unit tests and packaging.
> Hardware-dependent Windows audio integration tests are validated separately on real Windows systems.

The default GitHub Actions workflow excludes `Category=Integration` and `Category=Mutation` (and any
future `Hardware` / `RealAudio` categories) because a hosted runner has no audio endpoints. Running
those suites there would mostly return early and then be reported as passing — a false green.
Real audio verification is the maintainer gate `scripts/test-real-audio.ps1`.

### Note on SourceLink

`WinAudioRoute.csproj` enables SourceLink only when a `.git` working tree is present next to the
project. The 0.1.0 packages were produced from a working tree without git history, so they
intentionally carry repository metadata but **no source-link mapping**; the build does not emit
misleading links. Running `git init` and re-packing enables SourceLink automatically.
